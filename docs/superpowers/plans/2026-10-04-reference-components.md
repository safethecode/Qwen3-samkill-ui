# Reference component generation

The user requires reference-level commercial UI quality and explicitly asks to apply reference-decompose in units a local model can understand. Current file-based splitting loses component ownership, density and assembly relationships. This change provides a static-reference pilot, not an automatic commercial-quality certification.

## Contract

Preserve observed source regions, chosen implementation values and unknown behavior separately. A supplied component plan contains a shared visual contract, host-owned shared CSS, reference provenance, semantic elements with individual prompts/assets, and explicit assembly/sample templates. Each local request receives shared context plus one element, not the full page implementation task. Reuse upstream E/O records and corrections instead of inventing new observations.

## Implementation

1. Add a component-plan compiler with tests for missing/duplicate slots, escaped component scope, invalid output and deterministic assembly. Every element emits one HTML root and locally scoped CSS. Reject scripts, inline handlers and undeclared image assets. Preserve required labels and source assets.
2. Add sequential local component generation with bounded per-element attempts, raw response evidence and input-bound checkpoints. Assemble the accepted element outputs without another model rewrite. Generate standalone samples using the same available width and CSS as their assembly slots. Record all host assistance.
3. Prepare a Round 02 plan from inspected upstream analysis and corrected P1/P2/P3, explicitly identifying adapted content and unknown original behavior. Keep the existing font experiment and evidence separate.
4. Run the local model, capture elements and assembly at matching widths, and inspect source/current side by side. Preserve failure evidence and do not infer whole-page approval from individual components or functional counts. Add further cases only after the pilot exposes its limitations.

## Validation

Unit tests exercise compiler boundaries and checkpoint freshness. Browser evaluation checks fonts, assets, readable controls, labels, runtime errors and text stress. Direct reference comparison checks structure, proportions, density, spacing ownership, hierarchy and original icon roles. Exact source hashes bind every published result. Full 75-rule/eight-guide completion remains required and unknown states remain unapproved.
