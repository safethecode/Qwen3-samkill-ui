# Local UI operating rules

These rules consolidate failures observed in this repository. They apply to both the supervising agent and the local model; they do not certify the current outputs.

## Scope and reference fidelity

- Establish the requested platform before choosing layout. Mobile-only means a bounded mobile canvas with the same vertical order on large windows. Desktop adaptation needs explicit user scope or a supplied desktop reference. Unknown desktop CSS is not authorization to create it.
- Do not invent branded headers, additional sections, metrics, reviews or decorative content. Keep developer-facing evaluation text, demo notices and implementation details in reports rather than product UI unless requested. Preserve license/provenance records outside the visible flow.
- Inspect actual reference pixels, not just search snippets or a verbal summary. Use relevant UI Bowl tools, not unrelated analytics/MAU calls. Preserve sanitized retrieval metadata; never publish OAuth secrets or signed asset URLs.
- Separate observation, implementation decision and unknown. A screenshot does not reveal original CSS, fonts or hidden modal states. Adaptation must preserve the observed relationship, not fabricate supporting facts.

## Decompose before generation

- Read upstream reference-decompose and its element contract. Start with screen purpose, entry/return routes, canvas, semantic groups and state hierarchy. Then split bounded elements with parent/sibling ownership, spacing, typography, assets and verification.
- Detail screens need a real accessible return route, including direct entry. Test navigation rather than checking for an arrow alone.
- Preserve the reference's section grouping. For gray-canvas/white-section references, use surface and space rather than hr elements or thin border dividers. This is not a universal mandate to cardify every UI.
- Keep price, favorite and primary action semantically distinct. Bound supporting controls with a quiet surface where observed or requested. Limit crowded rows through declared relationships.
- Success state has one primary outcome heading; product and reservation facts belong in a subordinate summary. Hide stale form headings and duplicate product blocks. Verify actual transitions and saved-state reopening.
- Shared assembly owns cross-component layout. Model fragments must receive the actual contract, relevant guide text and permitted assets. A filename or skill link alone is not delivery. Avoid dumping every guide into every bounded request.

## Local execution and repair

- Confirm the actual backend, model, quantization and request settings. Keep Ollama available and inspect active clients before starting inference. Run one inference job at a time.
- Retain original responses and exact source/harness bindings. Distinguish model generation, local-model repair, host markup/layout and host behavior changes. Never attribute manual edits to Qwen.
- Split long generation into semantic units with stable shared contracts and resumable checkpoints. Repair only diagnosed failures with bounded patches; reject scope escapes, overlapping patches and changed input bindings.
- Use explicit bounded transport deadlines; repeated five-minute disconnects require diagnosis rather than repeating the same request. Thinking mode is an experiment, not presumed quality improvement; compare completed output, time and failures.
- Preserve rejected attempts and before/after evidence. Correct conflicting inputs before blaming model capability. For text-bearing controls, min-height and natural growth must not be contradicted by a fixed-height prompt.

## Verify actual rendering and behavior

- Use real licensed images, supplied fonts and official icon assets. Confirm loaded font identity and actual rendered icons, not only declared CSS or successful requests. Do not hand-draw replacement icons or invent asset names.
- Check complete HTML/CSS, valid field labels, actual select options and browser console/runtime behavior. Malformed tags can silently remove options even if their strings remain in source.
- Inspect mobile/narrow and wide-window captures, 200% text and separate spacing stress. Use unitless line-height, normal wrapping and natural control growth. Do not hide overflow, shrink text or drop content to pass.
- Test booking, validation, reload, cancel, focus return and storage faults. Preserve the existing record on failed cancellation; do not replace user content with unsafe HTML. Impossible dates and malformed saved data are invalid.
- Validate declared maxWidth, vertical ordering, ownership, surfaces and state hierarchy in their applicable states. Unvisited states remain unverified. Gates supplement direct visual comparison; they do not replace it.
- Compare original rounds and independently planned services over repeated fresh runs. Do not claim unattended reference parity from a manually assisted single page, functional totals or a single successful repair. Keep all applicable catalog/guide findings and remaining failures visible.

## Delivery

No code comments, private machine paths or credentials in published work. Preserve unrelated user work. Use separate logical commits, retain source-bound evidence and point to the current preview rather than an obsolete run. Continue authorized work without routine approval requests, and report limitations honestly.
