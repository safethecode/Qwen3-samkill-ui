# 한국어 제품 문구 기준

근거: 사용자가 제공한 김자유(토스 UX Writer), 「토스의 8가지 라이팅 원칙들」, 2022-11-15 본문. 다음은 원문을 제품 제작에 적용하기 위해 정리한 지침과 새로 만든 예시다. 현재 토스의 전체 내부 정책이나 공식 인증 지침이 아니다. 댓글·메뉴·푸터는 근거에서 제외했다.

## 목소리와 상황

기본 가치는 **명확함, 간결함, 친근함, 존중, 공감**이다. 제품의 목소리는 유지하되 상황에 맞게 말한다. 실패 안내는 차분하게, 중요한 일을 마친 순간은 짧게 축하할 수 있다. 모든 화면을 같은 감탄사·사과·농담으로 꾸미지 않는다. 한국어 어조가 정해지지 않았다면 쉬운 해요체를 기본으로 삼고, 명시된 브랜드 어조가 있으면 따른다.

## 여덟 가지 점검

| 원칙 | 확인할 질문 | 실제 적용 |
|---|---|---|
| 1. 다음 행동을 예상하게 쓰기 | 버튼을 누른 직후 무슨 일이 일어나는지 알 수 있는가? | 설문으로 가면 ‘설문 참여하기’, 실제 결제면 금액과 결제 행동. 장래의 혜택을 당장 받는 것처럼 쓰지 않는다. |
| 2. 필요 없는 단어 덜기 | 지워도 뜻·조건·확실성이 같은가? | 의미 없는 ‘정상적으로’, ‘성공적으로’, 반복 호칭 등을 검토한다. 실제 구분에 필요한 단어는 남긴다. |
| 3. 반복하는 문장 덜기 | 설명이 제목과 같은 말만 반복하는가? | 완료 제목 아래 완료 사실을 다시 쓰지 않는다. 날짜·다음 행동 등 새 정보가 없으면 설명을 생략한다. |
| 4. 지금 필요한 정보에 집중하기 | 지금 선택에 필요한 내용이 먼저 있는가? | 선택지를 구별하는 정보부터 쓴다. 배경 설명은 필요할 때 읽게 하되 비용·조건을 숨기지 않는다. |
| 5. 말하듯 쉽게 쓰기 | 사람에게 그대로 말해도 자연스러운가? | 추상 명사와 긴 피동문을 쉬운 동사로 바꾼다. 한 문장에 핵심 메시지 하나를 담되 기계적인 글자 수 제한은 두지 않는다. |
| 6. 선택을 존중하기 | 거절하는 사람을 탓하거나 겁주지 않는가? | 사실에 맞는 선택과 결과를 제시한다. ‘포기’, ‘손해’, 가짜 긴급성으로 행동을 밀어붙이지 않는다. 실제 기한·결과는 중립적으로 설명한다. |
| 7. 누구나 이해할 말 쓰기 | 특정 업계·세대만 알아듣는가? | 불필요한 외래어·은어·밈을 쉬운 말로 바꾼다. 제품명과 대상 사용자에게 필요한 전문 용어는 정확히 유지한다. |
| 8. 상황에 맞게 공감하기 | 이 정보를 받는 순간 어떤 마음일지 고려했는가? | 상환 완료 같은 이정표는 사실과 짧은 축하를 함께 전한다. 모르는 노력·기간·감정은 단정하지 않고 오류에 억지 위로를 붙이지 않는다. |

간결함은 단어 → 화면의 문장 → 화면 사이의 정보 순서로 확인한다. 사용자가 알아야 할 금액·기간·불이익을 삭제해서 짧게 만들지 않는다.

## 번역투를 고치는 방법

다음은 감지 신호이며 일괄 치환 규칙이 아니다. 먼저 누가 무엇을 했고 실제 상태가 어떻게 바뀌었는지 확인한다.

| 거친 문구 | 자연스러운 문구 | 전제/주의 |
|---|---|---|
| 고객님의 구독에 대한 자동 갱신 비활성화 처리가 성공적으로 수행되었습니다. | 자동 갱신을 껐어요. | 자동 갱신 해제가 실제로 확인됐을 때. ‘구독 종료’와 혼동하지 않음 |
| 설정 변경을 통해 알림의 수신을 관리할 수 있습니다. | 설정에서 알림을 켜거나 끌 수 있어요. | 실제로 두 행동을 지원할 때. 가능성을 완료 사실로 바꾸지 않음 |
| 이메일 주소의 입력을 진행해 주세요. | 이메일 주소를 입력해 주세요. | 명사+진행을 직접 행동으로 바꿈 |
| 당신의 계정이 성공적으로 생성되었어요. | 계정을 만들었어요. | 계정 생성 완료 확인. 불필요한 소유격·완료 수식 제거 |
| 더욱 원활한 경험을 제공하기 위해 권한 허용이 필요합니다. | 사진을 올리려면 사진 접근을 허용해 주세요. | 실제 권한 목적이 사진 업로드일 때만. 권한 종류를 지어내지 않음 |
| 온보딩을 컴플리트하고 베네핏을 확인하세요. | 가입을 마치고 혜택을 확인해 보세요. | 이 온보딩이 실제 가입이고 확인할 혜택이 있을 때만 |

‘~에 대해’, ‘~를 통해’, ‘~에 있어서’, ‘~에 의해’, ‘~의 ~의’, ‘~되어지다’, ‘~처리를 진행하다’가 겹치면 문장 구조를 고친다. 자연스러운 용법까지 모두 지우지 않는다. ‘환불’과 ‘결제 취소’, ‘자동 갱신 해제’와 ‘이용 종료’처럼 제품 의미가 다른 말을 편의상 바꾸지 않는다.

소리 내어 읽듯 검토하되 실제 음성 테스트를 하지 않았다면 했다고 쓰지 않는다. 표준 약어·고유명사·필수 고지 원문을 억지로 번역하지 않는다. ‘~할 수 있어요’가 가능성이나 권한을 나타내면 그대로 보존한다. ‘없을 수 있어요’를 ‘없어요’로 단정하지 않는다.

## 화면 단위 예시 — 가상 제품

### 다음 화면 예측

전제: 지금 버튼은 원하는 브랜드를 묻는 선택 설문으로 이동하며 혜택을 지급하지 않는다.

- 제목: 원하는 브랜드를 알려주세요
- 버튼: 설문 참여하기
- 보조 행동: 건너뛰기
- 배제: ‘혜택 받기’, ‘다른 곳에서 바로 결제’처럼 현재 동작과 다른 약속.

### 반복 설명 줄이기

전제: 구독 취소 완료, 이미 결제한 이용은 10월 31일까지 유지, 이후 청구 없음.

- 제목: 구독을 취소했어요
- 설명: 10월 31일까지 이용할 수 있어요. 추가 요금은 없어요.
- 배제: ‘구독 취소가 정상적으로 완료되었습니다’라는 중복 설명.

### 비용과 선택권

전제: 지금 3,900원 결제, 이후 매월 3,900원 자동 결제.

- 제목: 월 3,900원으로 이용해요
- 설명: 지금 3,900원이 결제돼요. 이후 매월 3,900원이 자동 결제돼요.
- 주요 버튼: 3,900원 결제하기
- 보조 행동: 나가기
- 배제: ‘무료로 시작’, ‘혜택을 포기하시겠어요?’. 나가기 동작도 실제 지원하는 경로에 연결한다.

### 완료 순간의 공감

전제: 대출 전액 상환을 확인했다.

- 제목: 대출을 모두 갚았어요
- 설명: 축하해요!
- 배제: 확인되지 않은 ‘3년의 노력’, ‘이제 걱정 끝’, ‘신용점수가 올랐어요’.

축하가 매 화면의 필수 요소는 아니다. 기능적 상태에는 사실만으로 충분할 수 있다. 중요한 완료 순간에서 짧은 공감이 적합한지 판단한다.

## 전달 전 확인

### 조작 의미와 번역 문자열

토글은 켰을 때의 상태를 바로 알 수 있게 쓴다. ‘알림을 받지 않기’가 켜짐과 겹쳐 혼란스럽다면 ‘알림 받기’처럼 긍정 상태를 검토하되 저장값의 실제 의미까지 함께 대조한다. 문구만 뒤집고 설정 동작은 반대로 남기지 않는다. 파괴적 확인 버튼은 ‘예’보다 ‘문서 삭제’처럼 즉시 결과를 드러낸다. 영어 verb-first를 한국어 어순에 강제하지 않는다.

번역을 지원하는 제품에서는 조사·수량·동사를 조각 문자열로 이어 붙이지 않고 완전한 메시지와 변수로 관리한다. 한국어 조사 처리·수량·날짜 형식과 제품 용어를 확인하고 같은 동작의 메뉴/버튼/완료 안내를 함께 대조한다. 한국어 전용의 작은 문구 수정을 새 번역 시스템 구축으로 확대하지 않는다.

### 탐지 신호와 제품 사실

‘혁신적인’, ‘직관적인’, 기계적인 삼단 나열처럼 구체적 역할이 없는 표현을 줄인다. AI 탐지기의 일치는 단서이며 고유명사·인용·검증된 수치를 자동 삭제하지 않는다. 구체적으로 쓰려고 속도·성과·사용자 수를 발명하지 않는다. 예를 들어 ‘검색 40% 단축(내부 실험, 20명, 기존판 대비)’에서는 수치와 조건을 보존하되 무엇을 단축한 것인지 불명이면 ‘검색 시간’이라고 채워 넣지 않는다.

빈 결과에는 조회 조건과 실제 가능한 복구 행동을 전달하되 내용이 생겨도 필요한 저장 범위·비용·조건은 빈 화면에만 두지 않는다. 같은 오류가 반복되면 안내 문구 외에 입력 제약·전이·복구 설계의 문제인지 구별한다. 문구 요청에서는 수정 문자열을 제공하고 흐름 문제를 별도 전달한다. 확인되지 않은 네트워크 원인이나 안전한 재시도를 약속하지 않는다.

### 최종 대조

8원칙 중 문제를 발견한 항목은 C-ID와 수정 이유에 연결한다. 적용 대상이 아니면 이유를 남기고 억지로 문구를 추가하지 않는다. 마지막으로 숫자·날짜·조건·부정/선택·불확실성·즉시 행동을 원래 제품 사실과 대조한다. 그다음 실제 화면이 있으면 줄바꿈·잘림·접근 가능한 이름을 확인한다. 텍스트 검토와 렌더 검증 결과를 구분한다.
