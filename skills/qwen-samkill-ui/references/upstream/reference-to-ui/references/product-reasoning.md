# 제품의 본질에서 배치 결정하기

목표는 레퍼런스와 아이디어를 결합해 사용자가 실제로 쓸 수 있는 좋은 제품을 구현하는 것이다. 아래는 사용자가 지정한 OpenClone Douglas 자료의 고객 문제·가치 중심 관점을 UI 설계에 옮긴 **이 패키지의 적용 방식**이다. 인물을 사칭하거나 그의 말투·투자 조언을 제품에 적용하지 않는다.

## 디자인 전 짧은 정의

기존 요구와 자료에서 다음을 정한다. 정보가 충분하면 질문을 반복하지 않는다. 미확인 고객 가설은 가설로 남긴다.

- 누구인가: 특정 사용자와 지금의 사용 상황.
- 무엇이 어려운가: 사용자가 이해·비교·결정·실행하려는 일과 현재 마찰.
- 무엇이 달라져야 하는가: 이 화면에서 완료할 핵심 행동과 성공 상태.
- 필요한 정보는 무엇인가: 그 결정을 내리는 데 필요한 데이터·조건·가격·신뢰 근거.

‘대시보드를 만들자’에서 멈추지 않는다. ‘판매자가 지연 주문을 찾아 발송 대상을 정한다’처럼 구체적으로 쓴다. 시각적 개성도 이 과제와 브랜드를 더 잘 드러내도록 설계한다.

## 요소를 배치하는 기준

중요한 영역/요소에 `E-ID | 필요한 사용자 판단/행동 | 보여줄 정보 | 위치·크기·강조 이유 | 삭제/뒤로 미뤘을 때 영향 | 검증`을 기록한다. 같은 역할의 반복 요소는 묶는다.

1. 정보 확인 → 비교/선택 → 결과 예상 → 실행의 관계를 정하고 읽기 순서로 옮긴다. 실제 사용 빈도·위험·내용 길이를 근거로 위계를 정한다.
2. 주요 행동은 결정에 필요한 정보와 가까이 둔다. 공간이 비어서 KPI·카드·소개 문장을 추가하지 않는다.
3. 장식·이미지·큰 글자도 브랜드 인식이나 콘텐츠 이해를 돕는 구체 역할이 있으면 사용할 수 있다. 핵심 정보를 가리는 비용과 비교한다.
4. 레퍼런스에서는 해결 원리와 시각 문법을 추출한다. 다른 서비스의 정보 구조를 그대로 가져오기 전에 우리 과제에 맞는지 확인한다.
5. 사용자가 요청한 아이디어는 해결하려는 마찰과 기대 효과를 명시해 더한다. 새로움의 개수를 채우거나 여러 제품의 특징을 무작정 합치지 않는다.

## 내용의 의미와 묶음

시각 스타일을 정하기 전에 정보가 답하는 질문을 구별한다. 항목 소개는 어떤 대상인지, 이용 조건은 내가 이용할 수 있는지를 설명한다. 같은 조건 범주의 사실을 아이콘이나 글자 크기가 다르다는 이유만으로 별도 의미 영역으로 분리하지 않는다. 예를 들어 반려동물 카페의 실내/마당 입장, 크기 제한, 이동가방은 모두 동반 조건에 속한다. 설명이 필요하면 대상의 특성을 짧게 쓰되 확인되지 않은 실제 서비스를 꾸며내지 않는다. 위험이나 결정에 중요한 조건은 그룹 안에서도 필요한 강조를 유지한다. 이 사례의 정확한 카드 순서를 모든 제품에 강제하지 않는다.

상위 제목이 이미 한정한 정보는 반복 필요성을 검토하고, 전체/저장 등 맥락이 사라지는 뷰에서는 식별 정보를 보존한다. 레퍼런스의 가격이나 메타데이터도 현재 제품의 선택에 필요한지 판단한다. 메뉴 가격 제거 사례를 실제 예약 비용·추가 요금까지 숨기는 규칙으로 확대하지 않는다.

## 레퍼런스와 새 아이디어 결합

`채택한 레퍼런스 원리 | 유지할 시각 규칙 | 새 아이디어 | 해결하려는 마찰 | 예상 비용/충돌 | 확인할 사용자 행동`으로 결정한다. 단순 재현을 요청받았다면 그 범위에 맞춘다.

가상 주문 관리 예: 주 레퍼런스의 촘촘한 행·금액 정렬을 유지한다. 사용자가 지연 주문을 먼저 처리해야 한다면 지연 필터와 선택 주문의 발송 요약을 추가할 수 있다. 이는 KPI 장식이 아니라 대상 확인을 돕는 아이디어다. 실패 기준에서 행별 행동 소음이나 중복 CTA가 잡히면 요약의 역할·범위를 검증하며 배치를 수정한다.

완료 기준은 두 축이다. **제품 기준:** 핵심 행동·상태·콘텐츠가 작동하고 필요한 정보를 찾을 수 있는가. **디자인 기준:** 상세 분석·토큰·의도한 개성이 구현됐고 제외 목록과 실패 기준을 통과했는가. 한 축의 통과로 다른 축을 대체하지 않는다. 작은 범위부터 구현·확인하고 발견한 문제를 수정한다.

## 사례에서 판단 관점으로 일반화

배치 판단의 단위는 특정 버튼 이름이나 행 템플릿이 아니라 사용자의 과제와 요소 사이의 관계다. 모든 요소에 대해 필요성 → 전달할 정보/행동 → 적용 범위 → 다른 요소와의 관계 → 읽고 행동하는 순서 → 강조·밀도 → 위치를 판단한다. 같은 범주라는 이유만으로 붙이지 않고, 역할이 다르다는 이유만으로 무조건 떼지도 않는다. 함께 있을 때 이해가 쉬워지는지, 서로 경쟁하거나 잘못된 관계를 암시하는지가 기준이다.

실패 사례는 관찰된 문제와 원인을 보존하는 증거다. 사례에 제안한 위치·행 분리·스타일은 당시 맥락의 해결 후보이며 다른 화면의 고정 정답이 아니다. 레퍼런스에서도 요소 좌표보다 관계와 위계가 작동하는 이유를 추출한다. 배치를 바꿀 때는 유지/이동/묶기/분리/삭제 중 과제에 맞는 대안을 비교하고 실제 화면에서 판단 근거를 확인한다. 사용자의 명시적 금지·요구는 유지하며 ‘맥락에 따라’라는 말로 확인된 실패를 합리화하지 않는다.

## 행동의 적용 범위와 위치

버튼을 놓기 전에 `행동 | 실제 변경 대상 | 범위(화면/섹션/항목/선택 집합) | 소속 영역 | 표시 조건`을 정한다. 헤더 오른쪽이 비어 있다는 이유로 섹션 행동을 올려놓지 않는다. 레퍼런스의 버튼 위치도 원래 적용 대상과 우리 제품의 대상이 같은지 확인한 뒤 채택한다.

- 화면 전체에 적용하는 행동은 화면 도구 영역, 목록 전체의 편집은 목록 제목/도구 영역, 항목 하나의 수정은 해당 항목, 선택 항목의 일괄 행동은 선택 상태의 도구 영역을 우선 검토한다. 위치만으로 대상이 모호하면 라벨과 그룹 구조를 함께 고친다.
- Todo의 목록 편집은 날짜/달력을 포함하는 화면 헤더보다 할 일 목록에 속하도록 배치한다. 임시 ‘예시 목록’ 문구가 사라져도 소속과 발견 가능성을 유지해야 한다. 이는 모든 편집 버튼을 하단으로 내리라는 규칙이 아니다.
- 편집 모드 진입 같은 보조 행동을 주요 생성 CTA와 같은 강조로 만들지 않는다. 필터와 편집은 같은 목록에 적용되어도 조회 조건 변경과 관리 모드 진입이라는 역할이 다르다. 같은 섹션에 속한다는 이유만으로 한 줄의 동급 조작으로 묶지 않는다. 빈 목록에서 실행할 대상이 없으면 숨김/비활성 등 적절한 상태를 정하고, 편집 종료·선택 취소는 해당 상태에서 찾을 수 있게 한다.

검수 시 ‘무엇에 적용되는지 누르기 전에 알 수 있는가’를 확인한다. 날짜 변경·필터·선택·빈 상태에서 실제 적용 집합과 시각적으로 암시한 범위가 일치해야 한다. 버튼 이동으로 핵심 행동이 긴 목록 끝에 묻히거나 키보드 순서가 어긋나지 않는지도 확인한다. 기능이 존재한다는 이유만으로 위치가 적합하다고 판정하지 않는다.

### 소속을 정한 뒤 행의 역할도 검증

각 시각적 묶음이 사용자의 어떤 판단과 행동을 돕는지 설명한다. 행·열·패널 등 레이아웃 형식이나 탐색/관리 같은 분류에 판단을 제한하지 않는다. 요소별 소속이 맞아도 행 안에서 서로 다른 행동이 같은 무게로 경쟁하면 배치 실패다. 아이콘·테두리만 다르게 해서는 역할 충돌이 해결되지 않는다.

사용자가 지적한 Todo의 해결 후보는 조회 행을 독립시키고 편집을 목록 요약과 연결하는 것이다. 이는 실제 화면으로 검증할 후보이며 유일한 정답이 아니다. ‘예시 목록’ 표시의 필요성과 자리를 함께 검토해 기존 줄에 편집까지 덧붙여 혼잡하게 만들지 않는다. 제거하면 안 되는 정보는 보존한다. 행을 나눈 뒤에도 간격·정렬·강조로 목록과의 관계를 유지하고 좁은 폭·긴 문구·편집 종료 상태에서 확인한다.

이 교정을 모든 도구 모음의 서로 다른 행동 금지로 확대하지 않는다. 다른 제품에서 한 줄을 공유하려면 사용자의 작업 흐름, 그룹 구분, 위계와 실제 폭에서의 명확성을 근거로 판단한다. 이 Todo 실패를 일반적인 도구 모음 관례로 정당화하지 않는다. 대안은 단순 좌표 이동이 아니라 행의 목적과 시선 흐름을 비교해 선택한다.

저장/보관처럼 탐색과 목적이 다른 뷰는 원래 목록의 날짜·예약 행동·중복 제목을 그대로 복제하지 않는다. 다시 찾고 비교하는 데 필요한 식별·소개·조건을 우선하고 실제 실행은 적절한 상세 흐름으로 연결할 수 있다. 긴급 실행이나 날짜가 저장 대상 자체를 식별하는 제품에서는 이를 생략하지 않는다. 빈 화면은 목록 내부뿐 아니라 남은 화면 공간과도 정렬을 판단한다.

내역 화면에서는 항목을 꾸미기 전에 사용자가 어느 기간의 몇 건을 보고 있는지, 어떤 항목에 행동하는지 판단할 수 있는지 확인한다. 조회 기간·수량·상태·정렬을 과제에 맞춰 선택하고 기간 기준(생성일/방문일 등)과 경계를 실제 데이터 동작에 연결한다. 주 제목·그룹 제목·항목 상태가 같은 의미를 반복하면 필요한 식별을 보존하며 중복을 걷어낸다. 항목 행동은 소속 위치만으로도 충분한지 실제 판독하고, 모호하면 대상 이름·날짜 등으로 구체화한다. 항목이 적거나 기간이 무관한 제품에 필터를 기계적으로 추가하지 않는다.
