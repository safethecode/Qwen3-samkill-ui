# 실제 내용으로 검증하는 타이포그래피

글자·폰트·줄바꿈·말줄임을 설계하거나 변경할 때 읽는다. 크기 하한은 [UI 구성 기준](ui-composition.md#글자-크기-하한), 색은 [토큰 계약](design-tokens.md)을 따른다. 한글 본문, 도구의 수치, 랜딩의 제목을 같은 수치 프리셋으로 만들지 않는다.

## 폰트 선언과 실제 렌더

`역할 | 사용 글꼴/대체 글꼴 | 지원 글자·굵기 | 크기/행간/자간 토큰 | 로딩 전후 증거`를 연결한다. CSS family 이름은 실제 사용된 글꼴의 증거가 아니다. 한글·영문·숫자가 서로 다른 fallback으로 표시되는지, 필요한 굵기를 실제 파일이 제공하는지 확인한다.

가변 폰트는 실제 지원 축을 확인하고 일반 굵기·숫자 정렬은 `font-weight`, `font-variant-numeric`처럼 의미 있는 CSS 속성을 우선한다. `font-synthesis: none`을 전역으로 넣기 전에 로딩 실패와 대체 글꼴에서도 강조가 남는지 확인한다. 시스템 글꼴만 쓰는 제품에 웹폰트를 추가하지 않는다.

폰트 미로드·지연·완료 상태를 같은 내용과 폭에서 비교한다. 첫 렌더의 글자 실종, 교체 후 CTA 밀림, 숫자 폭 변화, 굵은 상태의 줄바꿈을 검사한다. 계산 스타일 조회와 실제 폰트/화면 판독을 구별한다.

## 읽기 폭과 줄바꿈

- 제목·본문·라벨·수치의 역할로 위계를 정한다. heading 태그 번호가 시각 크기를 자동 결정하지 않는다. 제목을 키우거나 설명을 줄이면 기존 max-width도 재검토한다.
- 영문 행 길이 예시를 한글 글자 수로 복사하지 않는다. `ch`는 해당 폰트의 숫자 0 너비 기준이다. 실제 한글·공백 없는 URL·혼합 제목으로 읽기 폭을 판단한다.
- `word-break: keep-all`은 어절을 지키지만 긴 고유명사나 URL을 넘치게 할 수 있다. 필요한 영역의 `overflow-wrap`, flex/grid 최소폭, 줄바꿈을 함께 검증한다. `balance/pretty`는 해당 브라우저와 문구에서 결과를 보고 채택하며 모든 본문에 강제하지 않는다.
- 기본·200% 글자와 지원하는 좁은 폭에서 조사만 남는 줄, 단위/수량의 분리, 여러 줄 행간과 버튼 가림을 본다. 수동 `<br>`로 한 폭만 맞추거나 자간·transform 축소로 하한을 우회하지 않는다.
- 사용자가 글자 간격을 늘려도 내용을 읽고 조작할 수 있어야 한다. 웹의 해당 언어/문자에서 적용되는 [WCAG 텍스트 간격 시험](https://www.w3.org/WAI/WCAG22/Understanding/text-spacing.html)은 행간 1.5배, 문단 뒤 2배, 자간 .12배, 단어 간격 .16배를 동시에 덮어써 내용·기능 손실을 확인한다. 이는 제품의 기본 스타일을 이 값으로 고정하라는 뜻이 아니다.

## 잘린 값과 숫자

식별·가격·조건에 필요한 내용은 우선 노출하거나 줄바꿈한다. 말줄임이 필요한 경우 전체 값을 터치·키보드로 읽는 경로를 둔다. hover tooltip이나 `title` 속성만으로 전체 값 접근을 통과시키지 않는다. 펼침/상세 이동의 실제 동작과 복귀 초점까지 확인한다.

표·타이머·바뀌는 금액은 `111`과 `888`, 자릿수 증가·음수·소수·단위로 정렬을 비교한다. 숫자 열에 tabular figures가 필요한지 확인하고 실제 폰트의 지원을 본다. 문장 속 숫자까지 모두 고정폭으로 바꾸지 않는다. 복사할 주소·ID·본문에는 전역 `user-select: none`을 적용하지 않는다.

## 입력·언어의 반례

모바일 입력은 실제 기기에서 글자 크기·확대·키보드와 caret을 확인한다. 작은 입력의 자동 확대 문제가 있으면 16 CSS px 이상으로 조정하는 방안을 검토한다. 16px 선언 후 transform으로 작게 보이게 하거나 viewport로 사용자 확대를 막지 않는다. 실물 Safari/IME를 실행하지 않았다면 그 검증을 브라우저 에뮬레이션으로 대체했다고 하지 않는다.

지원 언어 또는 사용자 입력에 RTL이 있으면 `lang/dir`, 논리 속성, 혼합 값의 `bdi`를 확인한다. 전화번호와 ID의 숫자 순서를 직접 뒤집지 않는다. 한글 전용 고정 문구에 새 번역 시스템을 만들지는 않는다.
