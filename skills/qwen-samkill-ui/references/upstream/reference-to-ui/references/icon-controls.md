# 아이콘의 표시 영역과 조작 영역

아이콘 버튼·아이콘이 있는 CTA·선택 상태·좁은 도구 모음을 설계하거나 검토할 때 읽는다. 출처와 의미, 순서는 [UI 구성 기준](ui-composition.md#로고와-아이콘)을 따른다. 이 문서는 실제 그림·슬롯·클릭 영역이 달라 생기는 문제를 다룬다.

## 네 영역을 구별한다

`실제 보이는 그림 | SVG viewBox/레이아웃 슬롯 | 버튼·label의 유효 조작 영역 | 초점 표시`를 각각 확인한다. 아이콘을 크게 그려야 클릭 영역도 커지는 것은 아니다. 반대로 SVG width만 늘리고 이벤트가 작은 자식에만 걸려 있으면 충분한 버튼이 아니다. 그림·라벨·배경 등 조작처럼 보이는 범위와 실제 작동 범위가 맞아야 한다.

그림의 내부 여백과 비대칭 때문에 박스 중심과 보이는 중심이 다를 수 있다. 라벨과 묶음 전체의 중심을 실제 최소 표시 크기에서 확인한다. 지원하는 세트의 기본 선 체계를 우선하고, 굵은 라벨 옆에서 너무 가늘거나 두꺼우면 지원하는 stroke 변형·크기·색을 비교한다. 24px grid의 stroke 수치를 다른 크기·세트에 그대로 복사하거나 16px로 축소했다는 이유만으로 흐리다고 판정하지 않는다. 공식 자산의 path를 임의 수정해 맞추지 않는다.

## 클릭 영역과 이웃 조작

웹의 [WCAG 2.2 SC 2.5.8](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)은 24×24 CSS px 또는 해당 예외를 확인한다. 터치 주행동은 44×44 CSS px 이상을 시작점으로 검토하되 기존 제품 기준을 우선한다. 24는 최소 적합성 기준이며 모든 조작의 권장 크기가 아니다. pt·dp·이미지 px를 CSS px와 동일하게 취급하지 않는다. 작은 본문 링크 등은 적용 조건을 확인하고 44 미만이라는 이유만으로 자동 실패시키지 않는다.

가능하면 button/label 자체의 크기와 padding으로 조작 영역을 확보한다. 작은 그림을 유지하려고 pseudo-element를 확장하면 다음을 검사한다.

- input 자체 대신 적합한 button/label 래퍼에 두고 실제 클릭되는지 확인한다. 체크박스와 연결된 라벨 사이에 작동하지 않는 구간이 없는지 본다.
- 이웃 컨트롤의 유효 클릭 영역을 침범하거나 겹친 z-index로 다른 행동을 가로채지 않는다. 공간이 부족하면 배치·간격·실제 컨트롤 크기를 조정하고 무조건 확장하거나 최소 기준 미만으로 축소해 덮지 않는다.
- 부모 overflow/clip, 투명 레이어, 고정 영역이 확장된 클릭 영역이나 focus를 가리는지 본다. `getBoundingClientRect` 한 개만으로 pseudo-element의 작동 범위를 증명하지 않는다.
- 각 조작의 중앙뿐 아니라 가장자리·이웃 사이·확장 영역을 실제 눌러 예상한 한 행동만 실행되는지 확인한다. 카드 링크 위 저장 버튼은 DOM 박스가 겹칠 수 있지만 실제 대상과 이벤트 전파가 분리돼야 하며 중첩 button/link를 만들지 않는다.

장식 레이어는 필요하면 `pointer-events: none`으로 아래 조작을 가리지 않게 한다. 닫기 동작이 있는 모달 배경은 장식과 구별하고 무조건 이벤트를 제거하지 않는다. 접근성 트리에서 숨기는 것과 포인터 이벤트를 통과시키는 것은 별개다.

## 상태·터치·방향

단색 기능 아이콘은 `currentColor`와 상태 토큰을 연결한다. 다색 브랜드 자산까지 일괄 치환하지 않는다. 세트가 지원하는 outline/filled 상태 쌍을 사용하되 선 아이콘에 임의 fill을 넣어 형태를 망가뜨리지 않는다. 채움이 적합하지 않으면 라벨·표면·다른 상태 신호를 쓰고 색이나 움직임만으로 상태를 전달하지 않는다.

아이콘 교체 시 슬롯 크기·라벨·접근 가능한 이름·초점을 보존한다. 두 그림을 겹쳐 전환하면 장식 그림이 중복 낭독되거나 숨은 레이어가 클릭을 가로채지 않는지 확인한다. 모든 교체에 blur/scale을 넣거나 라이브러리를 추가하지 않는다. [모션 기준](design-tokens.md#상태-전환과-모션)에 따라 실제 빠른 토글·취소·동작 줄이기에서 최종 상태를 검증한다.

hover는 hover 가능한 입력에서의 부가 피드백으로 다룬다. 터치에서 첫 탭 후 남은 hover를 선택으로 오해하지 않게 하고 pressed/selected/focus와 구별한다. 터치+포인터 혼합 기기도 관련 지원 환경에서 확인한다. 탭 강조를 제거했다면 대체 피드백을 검증하고, 전역 `touch-action: none`으로 스크롤·확대를 막지 않는다. 제스처 제약은 실제 필요한 표면에 한정한다.

RTL을 지원하면 읽기 방향에 의미가 연결된 뒤로/다음 아이콘만 제품 관례에 맞춰 검토한다. 로고·시계·재생 등 모든 아이콘을 일괄 반전하지 않는다. 실제 동작·라벨·좌우 배치의 의미가 함께 맞는지 확인한다.
