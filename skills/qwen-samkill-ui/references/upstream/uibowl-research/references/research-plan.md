# 여러 검색을 누적해 제품 전체에 적용하기

복합 제품 요청, 여러 화면/기능, 레퍼런스 추가·누적 요청에서 반드시 사용한다. 한 검색 결과를 제품 전체의 레퍼런스로 취급하지 않는다. 사용자는 이 패키지에서 필요한 여러 MCP 호출과 추가 결과 탐색을 기본 행동으로 요청했다. 호출별 결과 개수·인증·멤버십·요금/접근 한도는 그대로 지킨다.

## 검색 전에 제품 과제를 분해

핵심 제품과 보조 기능을 분리해 `B-ID | 사용자 과제 | 필요한 화면/요소/상태 | 기존 근거 | 검색 의도 | 확인 상태`를 만든다. 최신 메시지의 단어만 검색해 원래 제품을 잊지 않는다.

‘채팅으로도 생성하는 모바일 Todo’ 예시:

- B1 할 일 확인·완료: Todo 목록, 체크행, 상태 필터, 날짜/기한 표시.
- B2 대화로 생성: 입력, 전송, 해석 결과 확인, 실패/수정. 일반 대화방 목록만으로 충족되지 않는다.
- B3 두 과제의 전환: 모바일 탭/내비게이션, 선택 상태, 복귀와 초안 보존. 목록 또는 채팅 결과에 보이면 재사용하고 없으면 따로 조사한다.

각 핵심 분기는 관련 실제 화면 근거가 필요하다. 하나의 화면이 여러 분기를 충족하면 중복 검색하지 않는다. 기존 자료는 실제로 다시 확인하고 출처/관찰/채택 장점이 충분할 때만 재사용한다. 오래된 문서에 앱 이름이 있다는 이유로 covered 처리하지 않는다. 핵심 Todo의 품질이 부족하다는 피드백이 있으면 Todo 분기를 다시 연다.

## 서로 다른 의도는 별도 호출

‘한국 커머스 결제 바텀시트’는 한 의도 안의 복합 필터이므로 한 호출에서 교집합으로 검색한다. ‘Todo 목록과 채팅 입력’은 서로 다른 과제이므로 각각 호출한다. AND 검색에 `할 일 채팅`을 한꺼번에 넣어 두 범주의 교집합만 찾지 않는다.

각 분기의 첫 결과를 본 뒤 빈틈에 따라 다음 호출을 정한다. 이미지가 대화방 목록인데 입력창/응답이 필요하면 채팅 분기는 아직 부족하다. 현재 조건의 다음 페이지, 더 구체적인 화면/요소, 관련 앱의 화면을 확인한다. 같은 의도의 단어 변형만 무의미하게 반복하지 않는다. 다른 분기의 검색은 이전 검색의 재시도 횟수에 묶지 않는다.

사용자가 이미 여러 번 검색·누적을 요청했으므로 필요한 다음 페이지마다 ‘더 볼까요’를 다시 묻지 않는다. 현재 스키마의 page/has_more와 반환 결과를 확인한다. 끝 페이지·중복 결과·접근 제한에서는 페이지를 계속 올리지 않는다. 무료/멤버십 제한을 우회하지 않는다. 명시된 국가·업종·플랫폼·앱 제약을 조용히 바꾸지 않는다.

0건이면 같은 의도를 유지한 유의미한 표현으로 재시도하고, 계속 없으면 누락 분기를 유지한 채 다른 적절한 화면/컴포넌트/앱 접근을 검토한다. 화면 의도를 무관한 OCR로 대체하지 않는다. 새 호출은 찾으려는 근거와 달라진 접근을 설명할 수 있어야 한다. 더 시도할 합리적 경로가 없으면 not-found/blocked와 시도 이력을 남긴다. 이를 연구 완료나 시각 검증 통과로 바꾸지 않는다.

## 호출·출처·선택을 누적

기존 프로젝트 문서가 없으면 `design/reference-brief.md`에 아래 세 표를 유지한다. 매번 새 파일로 과거 후보를 없애지 않는다.

1. 호출 이력: `SC-ID | B-ID | 도구 | 실제 query/필터/page | 결과 수/has_more/오류 | 추가 호출 이유 | 반환 R-ID`.
2. 출처 목록: `R-ID | 앱/화면·원본 ui_url·화면 식별자 | 발견 SC-ID들 | 실제 확인한 이미지/상태 | 관찰 O/E-ID | 채택/보류/배제와 이유`.
3. 분기별 적용: `B-ID | 후보 R-ID들 | 선택한 장점 | D/Q-ID·구현 영역/토큰 | covered/partial/not-found/blocked | 남은 근거와 다음 행동`.

같은 원본 화면이 다른 검색에 나오면 R-ID를 유지하고 발견 SC-ID만 추가한다. 서로 다른 화면을 앱 이름이 같다는 이유로 합치지 않는다. 채택 취소도 이전 결정과 변경 이유를 보존한다. 서명된 이미지 URL·인증 토큰은 저장하지 않고 원본 ui_url과 확인 범위를 사용한다.

## 검색 종료와 구현 인계

호출 수나 모은 이미지 수로 종료하지 않는다. 핵심 분기마다 실제 관찰한 적합 후보와 구체적인 채택 장점이 있고, 인계 가능한 상세 정보가 있는지 확인한다. 단순 검색 요청의 결과 전달과 제품 전체 조사 완료를 구별한다. 한 분기에만 후보가 몰리고 다른 핵심 분기가 비어 있으면 완료가 아니다.

화면별 주 레퍼런스와 역할 있는 보조 레퍼런스를 정하고 공통 타입·간격·색/표면·아이콘 문법으로 조합한다. 채택 출처는 [Q-ID 품질 비교](../../reference-to-ui/references/reference-synthesis.md)로 구현에 연결한다. 여러 번 검색해 놓고 마지막 결과만 구현하는 것도 실패다. 이번 단계에서 구현하지 않았다면 적용 대상/검증 계획까지만 기록한다.

자료가 없는 상태에서 설계 가설은 진행할 수 있지만 해당 분기의 reference-unverified/unknown은 유지한다. 사용자가 요청한 핵심 기능을 목록에서 삭제해 covered 비율을 높이지 않는다. RUI-18은 분기 누락·단일 검색 고착·누적 유실·적용 누락을 판독한다.
