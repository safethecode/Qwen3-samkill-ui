# 컴포넌트 상세 분석

UI 설계/구현 인계와 세부 분석 요청에 사용한다. 주 화면의 서로 다른 유형·크기·중요도·보이는 상태를 목록으로 만든다. 버튼, 입력, 카드/행, 제목/본문, 내비게이션, 탭, 배지, 구분선, 이미지, 오버레이 중 실제 존재하는 항목을 다룬다. 모든 반복 행을 다시 분석하지 않고 대표 항목과 차이를 기록한다. 화면에서 잘렸거나 보지 못한 부분은 분석 범위 밖이라고 명시한다.

## 측정 원칙

- 근거 종류: 직접 이미지, 사용자 관찰, DOM computed style, 실제 SVG/디자인 파일 등. 직접 확인하지 않은 자료를 실측으로 부르지 않는다.
- 값의 종류: `measured / estimated / unknown`. 단위는 `image-px / CSS-px / rem / ratio` 등 좌표계를 포함한다. 추정이면 범위나 대략값을 쓰고 정확한 소수점을 만들어내지 않는다.
- 미리보기 배율, 원본 크기, CSS viewport, 기기 배율은 각각 구분한다. 충분한 변환 근거 없이 이미지 px를 CSS px로 옮기지 않는다. 원본 너비만으로 잘린 영역·배율·기기 DPR을 추정하지 않는다.
- 화면 경계부터 보이는 글자까지의 거리는 **시각적 거리**다. DOM 없이는 padding, margin, gap, line box, 아이콘 내부 빈 공간 중 무엇이 만든 거리인지 확정할 수 없다.
- 글자의 잉크 높이는 font-size나 line-height가 아니다. 보이는 아이콘 크기는 SVG viewBox나 터치 영역 크기가 아니다.
- 래스터에서 뽑은 색은 그 이미지의 합성 결과다. 압축·안티앨리어싱·투명도·그라디언트가 있는 픽셀을 원본 CSS 색/토큰으로 단정하지 않는다. 샘플 위치/방법이 없으면 ‘흰색으로 보임’처럼 기록하고 HEX를 꾸미지 않는다.
- 정지 화면으로 hover/focus/pressed/disabled의 색과 동작을 복원하지 않는다. 보이는 상태만 관찰하고 나머지는 후속 설계 대상으로 남긴다.

## 요소별 필수 관찰 항목

| 묶음 | 기록할 속성 |
|---|---|
| 식별/범위 | E-ID, R/O-ID, 역할, 위치/영역, 유형/변형/상태, 분석 여부 |
| 박스/배치 | 폭·높이, 정렬, 부모와의 관계, 다른 요소와 간격, full-width/내용 폭으로 보이는지; 실제 sizing 규칙은 별도 근거 |
| 여백 | 위/오른쪽/아래/왼쪽 내부 시각 거리, 외부 거리, 자식 간 gap, 행/열/섹션 간격. CSS padding/margin은 확인된 경우만 이름 붙임 |
| 글자 | 실제 라벨, 정렬, 크기·굵기·줄높이·자간의 관찰 범위, 줄 수, 줄바꿈/잘림, 글자색. 폰트 패밀리·실제 로드 서체는 확인한 범위만 |
| 색상 한 쌍과 표면 | 배경 + 글자 + 아이콘 + 테두리 색, 반경, 테두리 두께/스타일, 그림자, 투명도. 각 상태를 분리하고 대비 확인 여부 표시 |
| 아이콘 | 윤곽/채움/혼합, 선 굵기, 끝/모서리의 둥글기, 광학적 크기·박스 크기, 색, 글자와 gap·수직 정렬, 앞/뒤 위치. SVG 확인 전 패밀리·stroke 수치 단정 금지 |
| 행동/상태 | 보이는 선택·비활성·로딩 등, 알려진 행동, 미관찰 상태/터치 영역/키보드 동작 |
| 인계 | 채택할 규칙, 배제할 선택, 토큰화할 후보 역할, 미확인 값과 다음 확인 방법 |

해당 요소에 없는 속성은 `not-applicable`과 이유, 존재 여부/값을 모르면 `unknown`으로 쓴다. 배경색만 기록하고 버튼 글자색을 생략한 분석은 불완전하다. 같은 배경이라도 글자·아이콘 색과 굵기가 달라지면 다른 표현이다.

## 기록 형태

요소 목록: `E-ID | 역할/변형/상태 | 출처·영역 | inspected / user-reported / not-inspected | 상세 기록 위치`.

각 요소: `속성 | 관찰값 | measured/estimated/unknown | 단위·배율 | 근거/측정 방법 | 토큰 후보 역할`.

토큰 후보는 `action.primary.background`, `action.primary.foreground`, `control.padding.inline`, `icon.control.stroke` 같은 **의미 후보**다. 기존 토큰을 읽기 전 이미 존재한다고 주장하지 않는다. 불확실한 관찰값은 디자인 토큰의 확정값이 아니다.

## 가상 예시

사용자 관찰: 600×1200 미리보기, 파란 CTA에 흰 글자와 흰 윤곽 화살표, 둥근 선 끝. 좌우 경계에서 내용까지 약 24 image-px, 아이콘-글자 약 8 image-px, 글자 잉크 높이 약 14 image-px. 원본·배율·DOM 미상.

E1/primary/default: 배경 파랑, 글자/아이콘 흰색은 user-reported estimated; 정확한 HEX/대비 미상. 좌우 시각 거리는 약 24 image-px이고 상하 거리·실제 CSS padding은 unknown. 아이콘 간격 약 8 image-px는 CSS gap 확정값이 아니다. 폰트 크기/줄높이는 unknown이다. 아이콘은 outline/rounded caps로 관찰됐고 패밀리·선 굵기·박스 크기·join은 unknown이다. hover 등 다른 상태도 unknown이다.

인계: 해당 표현을 보존하되 기존 토큰을 확인한 후 필요한 값을 `chosen`으로 결정한다. 라이브러리의 기본 채움 화살표나 검은 글자를 자동 적용하지 않는다. 구현에서 CSS 단위·글자 박스·실제 렌더를 확인하고 원본과 같은 표시 조건으로 비교한다.
