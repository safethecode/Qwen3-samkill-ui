# 요소·프롬프트 계약

필드를 채우기 위한 장문 대신 실제 구현 선택을 제한할 정보를 적는다. unknown은 값과 확인 방법을 함께 기록한다. 기존 E/O/Q 표가 있으면 그 표를 확장한다.

## 각색 전 화면 스타일 계약

제품에 맞춰 색·표현을 바꾸거나 여러 레퍼런스를 조합할 때, 개별 요소값을 고르기 전에 다음 관계를 공유 계약에 둔다.

`원본 영역/관찰 → 눈에 보이는 효과와 해석 가설 → 유지할 관계 → 제품에서 바꿀 역할/값과 이유 → 실제 비교 증거/판정`.

관찰에는 바탕과 강조색의 면적·명도/채도 대비, 제목과 부가정보의 대비, 사진/그림/조작의 표현 차이, 요소 내부와 그룹 사이의 간격을 포함한다. 원본 제작자의 실제 선택 이유는 확인한 자료가 있을 때만 사실로 적고, 이미지로 추론한 이유는 가설로 표시한다. 정밀 분포를 측정하지 않았다면 상대적 관계로 남긴다.

커스텀 팔레트는 이 관계를 어떤 역할에 옮길지 정한 뒤 선택한다. 예를 들어 중립 검색과 강한 실행 버튼의 대비가 핵심이면 새 색상에서도 그 역할 차이를 구현하고 확인한다. 사진의 색을 화면 전체로 확장하거나 모든 조작을 같은 보조면으로 바꾸면 어떤 위계가 달라지는지도 계약에 드러나야 한다. 이번 제품의 HEX·색상명·간격값은 사례에 둔다.

색 변경이 없는 정확한 재현 요청에서는 원본색을 유지한다. 무채색 원본의 차분한 대비가 핵심이면 채도 높은 강조색을 새로 만들 필요가 없다. 기능상 필요 없는 광고·그림을 면적만 맞추려고 추가하지 말고, 그 영역을 덜어낸 뒤 전체 비중이 어떻게 달라지는지 비교한다.


## 입력 묶음

`입력 버전 | 출처 R-ID/파일/관찰 영역 | 원본 크기 | 비교 표시 폭·배율 | 원본 CSS/DPR 확인 여부 | 재현/각색/분석 범위 | 사용자 제약 | 에셋 출처`.

E-ID는 출처와 입력 버전 안에서 식별한다. 다른 화면·라운드의 같은 번호를 동일한 요소로 추정하지 않고, 교정 대상에는 R-ID/버전/E-ID를 함께 붙인다.

화면 트리는 부모 소속을, 관계 표는 부모만으로 알 수 없는 정렬·근접·비율·가림을 표현한다. 요소의 터치 영역과 보이는 도형, 글자의 line box와 잉크 크기를 구별한다.

## 요소 계약

| 항목 | 기록 |
|---|---|
| 식별 | E-ID, 출처 R/O와 영역, 역할, 부모, 형제, 실제 표시 상태 |
| 박스 | 관찰 영역과 단위/근거, 구현 폭·높이/min/max와 chosen 표시, 내용 길이에 따른 변화 |
| 여백/관계 | 사방 시각 거리, 내부/외부 소유권, 정렬 기준, 이웃 gap, 사진/텍스트 등 비율 |
| 내용 | 원문, 확신 없는 글자, 줄 수/줄바꿈/잘림, 짧은·긴 변형 |
| 표현 | 글자 역할·크기·굵기·줄높이, 배경/글자/아이콘/경계 조합, 반경·선/채움 |
| 아이콘이 있는 행동 | 실제 동작·아이콘 역할·순서 근거, 표시/누락 상태, 글자와의 시각 간격, 보이는 묶음의 정렬·빈 슬롯 처리 |
| 상태 | 실제 관찰과 미확인 동작, 연결할 행동/정적 범위, 상태별 추가 내용의 자리와 자신·형제 박스에 미치는 영향 |
| 재현 | 공유 계약 참조, 요소 프롬프트, 사용 에셋, 출력 컴포넌트, 조립 슬롯 |
| 비교 | 유지할 관계, 확인할 뷰포트/내용 변형, 원본/렌더 증거와 판정 |

일부가 가려진 요소는 보이는 내용과 보이는 컨테이너 경계를 각각 기록한다. 숨겨진 내용·높이가 unknown이어도 관찰된 상단 경계나 부모 소속까지 삭제하지 않는다. 경계가 원본에 보이지 않으면 새로 만들어 넣지 않는다.

‘작은 사진 카드’ 대신 ‘사진이 장소 박스의 왼쪽·위·아래 경계에 붙고, 선택 상자는 그 박스 밖 왼쪽에서 세로 중심을 맞춘다’처럼 쓴다. 이는 설명 방식의 예시이며 모든 카드의 배치 규칙이 아니다. 문장에 없는 여백·순서를 구현자가 보충해야 한다면 선택값으로 정하거나 미결로 밝힌다.

## 반복 묶음과 컨트롤의 표현 계약

목록을 각색할 때 **항목 안의 정보·행동이 한 묶음으로 읽히는지, 다음 항목과 어디에서 갈리는지**를 스크롤 상태에서도 확인한다. 간격만으로 부족하면 제품에 맞는 표면 단계를 선택하고 내부/외부 패딩 소유권을 기록한다. 교대 배경은 가능한 선택이며 모든 목록의 기본값이 아니다.

정보 태그를 채택하면 실제 조건과 표시 문구, 정적 정보/필터/행동 중 역할, 아이콘의 의미, 긴 내용의 줄바꿈을 계약한다. 같은 조건을 태그와 본문에 중복하지 않으며 조건을 줄이기 위해 예외·준비물·이용 제한을 삭제하지 않는다. 정보 아이콘을 검증·안전 보장으로 오해시키지 않는다. 태그나 보조정보를 추가한 뒤에는 사진/정보의 기존 상하단 관계를 다시 측정한다. 공유 행으로 읽혀야 하는데 한쪽만 고정 높이여서 마지막 정보가 밖으로 빠지면, 내용과 사진 crop을 보존하며 행의 높이 소유권을 조정한다. 원본이 의도한 서로 다른 높이를 무조건 같게 만들지는 않는다.

셀렉트 커스텀은 닫힌 필드와 펼친 옵션 중 실제 구현 범위를 명시한다. 공통 여백·화살표 자리·현재값·focus/disabled와 키보드 선택을 함께 확인하며, 네이티브 옵션을 유지했다면 팝업까지 커스텀했다고 하지 않는다.

반복되는 날짜·시간·선택 버튼은 [상태별 치수 안정성](../../reference-to-ui/references/design-tokens.md#반복-컨트롤의-상태별-치수-안정성)을 공유 계약에 연결한다. 상태 문구 하나가 형제의 행 높이까지 바꾸는지 별도로 검사한다. 토글은 저장값·ARIA와 실제 아이콘 채움/윤곽·색을 함께 비교한다. 누른 직후 hover가 겹친 상태, 포인터가 떠난 상태, 재진입/해제도 확인해 데이터만 바뀐 것을 시각적 활성화로 통과시키지 않는다.

## 실행용 프롬프트

공유 계약에는 화면 조건, 공통 토큰과 단위 근거, 사용자 제약, 에셋, 구현 범위를 둔다. 각 요소 프롬프트에는 **역할 → 부모/박스 → 자식 순서와 관계 → 실제 내용/변형 → 표현 → 상태 → 확인 조건**을 둔다. 조립 계약에는 요소의 읽기 순서, 그룹 내부/사이 간격, 공통 inset 소유자, 고정/흐름의 확인 상태와 이번 선택을 둔다.

구현에 전달하기 전에 선택한 고정 박스와 자식 크기의 합을 검산한다. 예를 들어 이름 줄높이 + 메타 간격 + 배지 줄높이·상하 패딩이 식별 영역 높이에 들어가는지 확인한다. 서로 맞지 않으면 원본 관계를 다시 보고 수치 또는 가변 높이 선택을 고친다. 줄바꿈이 늘어나는 좁은 폭에는 같은 고정 높이를 강제하지 않는다.

독립 표본과 조립은 같은 CSS뿐 아니라 같은 가용 폭에서 대조한다. 표본 페이지의 설명용 컨테이너 padding이 실제 컴포넌트 폭·줄 수를 바꾸지 않는지 computed box로 확인한다. 설명 여백은 설명 영역이 소유한다. 서로 다른 폭을 의도한 실험이면 해당 조건을 표시하고 동일 조건의 재현이라고 부르지 않는다.

이 묶음을 그대로 구현에 전달한다. 결과 코드를 보고 최초 프롬프트를 소급 작성하지 않는다. 원본을 보지 않는 구현 평가에서도 필요한 사진·서체 등 에셋을 명시적으로 전달할 수 있지만 UI를 포함한 전체 캡처를 레이아웃 에셋으로 전달하지 않는다.

## 교정 기록

`F-ID | 라운드/입력 버전 | 사용자 지적 또는 내부 관찰(구별) | 해당 E/관계 | 원본 기대/실제 결과 | 번역 누락·오독/구현 불이행/미확인 원인 | 수정 프롬프트 버전·변경 구절 | 수정 파일 | 재렌더 증거·판정 | 스킬에 올릴 조건·반례 또는 사례 한정`.

예: ‘사진이 너무 작다’는 지적을 ‘앞으로 모든 사진96px’로 저장하지 않는다. 원본은 사진이 부모 높이를 채우는데 결과는 내부 패딩에 의해 작아졌는지 확인한다. 확인됐다면 ‘사진의 경계 접촉과 부모 패딩 소유권을 명시한다’를 해석 기준으로 보완한다. 원본 자체에 사진 여백이 있으면 경계 접촉을 강제하지 않는 것이 반례다.
