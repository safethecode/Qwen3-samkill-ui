# 내용 경계와 연속 상태 검증

컴포넌트·폼·비동기 행동을 구현하거나 검토할 때 기존 화면 계약에 붙여 사용한다. [리뷰 기준](review-criteria.md)과 필수 게이트를 대체하지 않는다. 정상 상태와 오류 상태를 각각 캡처했다는 사실만으로 그 사이 전이를 검증했다고 하지 않는다.

## 실제 도달할 조건을 먼저 선택

대상 컴포넌트의 입력·슬롯·소비 화면·상태를 읽고 `조건 | 적용 근거 | 입력/전이 | 기대 | 실제 | 증거`를 만든다. 지원하지 않는 기능을 시험하려고 추가하지 않는다. 미적용은 도달하지 않는 근거, 미실행은 미검증으로 구별한다.

| 입력 축 | 적용할 때와 표본 |
|---|---|
| 길이·문자 | 외부/사용자/번역 문자열: 빈 값, 대표 길이, 실제 긴 값, 공백 없는 URL, 한글+영문+숫자·이모지 |
| 수량 | 반복 목록: 0·1·평소 수량·제품에서 가능한 많은 수량. 목록이 아닌 버튼에 대량 행 시험을 추가하지 않음 |
| 가용 폭 | 지원하는 최소/최대 viewport와 형제 때문에 압축된 컨테이너. 고정폭 표본은 실제 viewport의 media query·safe area 시험을 대신하지 않음 |
| 상태 | 실제 존재하는 loading/error/disabled/selected 및 오류+focus, 선택+hover 같은 도달 가능한 조합 |
| 환경 | 지원 테마·200% 글자·고대비·동작 줄이기·폰트/이미지 실패. 지원하지 않는 다크 모드를 새로 구현하지 않음 |

표본 페이지가 유용하면 프로젝트의 실제 컴포넌트를 import하고 기존 폰트·토큰·스타일을 사용한다. 모양만 다시 만든 복제품이나 검사 전용 CSS로 문제를 가리지 않는다. 테스트 데이터는 실서비스 쓰기와 분리한다. 표본과 실제 소비 화면을 모두 확인하고, 발견한 문제는 수정 권한 범위에서 수정 후 같은 조건으로 재검증한다. 한 번의 로드·보고 개수로 필수 검사 범위를 제한하지 않는다.

## 오류와 복구는 연속 실행

폼이면 입력→제출→처리 중→실패/결과 미상→수정 또는 재확인→재제출→완료를 실행한다. 비동기 행동이면 기다리는 중 화면 이동·취소·연속 조작·응답 순서 역전을 제품 경계에 맞게 시험한다.

확인할 불변 조건은 입력 보존, 처리 대상 식별, 중복 반영 방지, 오래된 응답의 현재 화면 덮어쓰기 방지, 복구 행동 접근이다. 성공 메시지만 보지 말고 실제 저장 상태와 UI를 대조한다. 응답 유실은 미저장 확정이 아니다. 조회/멱등성 API가 없으면 이를 구현됐다고 쓰거나 결과 미상에서 안전한 재시도를 보장하지 않는다.

오류를 없애려고 값을 지우거나 폼을 닫지 않는다. 입력별 오류는 해당 필드와 프로그램상 연결하고 수정 후 오래된 오류가 남지 않는지 본다. 반복 오류가 입력 형식·상태 설계에서 생긴다면 문구 수정으로 해결됐다고 하지 않는다.

## 접근성 상태의 수명

- 네이티브 label·button·link·form과 기존 위젯을 우선한다. placeholder로 label을 대신하지 않는다. 붙여넣기·자동완성·한글 조합 입력을 임의 차단하지 않는다. 검증 시점은 제품에 맞추되 입력 중인 미완성 글자를 오류로 반복 낭독하지 않는다.
- 요청 중 중복 제출을 막으면서 버튼 이름·처리 상태·초점을 유지한다. `aria-disabled`는 동작을 막지 않으므로 포인터·키보드·submit 경로를 모두 확인한다.
- 일반 결과 알림은 작업 초점을 빼앗지 않는다. 안정된 live region의 내용 갱신과 실제 낭독을 확인하고 긴급하지 않은 갱신을 반복 assertive로 알리지 않는다. DOM/접근성 트리 확인과 실제 스크린리더 낭독 결과는 구별한다.
- 오류·실행 취소·중요 조건의 유일한 경로를 자동으로 사라지는 toast/빈 상태에 두지 않는다. 필터 이동·결과 도착 후에도 필요한 안내와 복구 경로가 남아야 한다.
- 모달 열기→내부 키보드 이동→닫기→복귀를 실행한다. 원래 트리거가 삭제되거나 필터로 사라졌다면 의미 있는 다음 대상으로 초점을 보낸다. 비모달 패널에 무조건 focus trap을 걸지 않는다.

실제 기기·보조 기술·서버에 접근하지 못하면 그 항목만 미검증으로 남기고 독립적인 로컬 시험은 계속한다. 명세 요청은 이 조건과 예상 결과를 전달하는 `spec-only`이며 실제 실행 통과가 아니다.
