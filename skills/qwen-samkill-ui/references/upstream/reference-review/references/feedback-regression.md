# 사용자 교정의 재발 점검

사용자 교정이 있는 UI를 수정하거나 같은 패턴을 다른 화면으로 확장할 때 읽는다. 기존 [실패 목록](failure-catalog.json)의 관련 ID와 프로젝트 기준에 연결하는 판독 절차다. 별도 통과 목록을 만들거나 원래 검사를 줄이지 않는다. 특정 앱의 색·간격·행 구성을 공통 프리셋으로 배포하지 않는다.

## 수정 전에 확보할 것

기존 교정에서 `사용자 요구 | 실패 원인/잘못된 판단 | 적용 요소·화면·상태 | 현재 유효한 결정 | 반례/범위 | 실제 검증 | 미완료`를 확인한다. 기능 요청뿐 아니라 사용자가 지적한 스타일·느낌·정보 판단도 포함한다. 당시 구현 수단과 사용자의 목적을 구별한다. 예를 들어 ‘항목을 구별하라’와 ‘모든 목록에 회색 교대 배경을 써라’는 다르다.

목록·저장·예약처럼 같은 컴포넌트를 쓰는 뷰도 각각의 판단과 행동을 먼저 정한다. 공유 CSS의 변경은 모든 실제 사용처를 찾고 기본/빈 상태/필터/저장 해제/취소 후의 의미와 배치를 확인한다. 같은 피드백을 다른 탭에서 사용자가 다시 설명하게 하지 않는다.

## 판독 순서와 재발 신호

| 점검 | 실패로 볼 신호와 확인할 행동 | 연결 기준 |
|---|---|---|
| 레퍼런스와 각색 | 기능·색 일부만 비슷한데 전체 스타일을 통과시킨다. 원본의 색 면적/명도·채도, 그림·사진, 표면, 간격·밀도 관계를 실제 결과와 나란히 판독한다. 색 커스텀 이유는 관찰 효과와 연결하고 제작자의 의도를 아는 척하지 않는다. | RUI-16/17, [결합 기준](../../reference-to-ui/references/reference-synthesis.md) |
| 제품 정보의 필요성 | 레퍼런스의 가격·지역·날짜를 그대로 복제하거나 제목/그룹/항목에서 같은 상태를 반복한다. 해당 뷰에서 사용자가 판단할 사실을 남기고 혼합 지역·실제 비용·이용 제한 등 필요한 의미는 보존한다. | RUI-05/24, [제품 판단](../../reference-to-ui/references/product-reasoning.md) |

| 버튼 아이콘과 정렬 | 한쪽 배치나 CSS gap만 맞추고 실제 동작·아이콘 누락·보이는 묶음의 중심을 확인하지 않는다. 정상/누락 상태와 긴 라벨에서 [버튼 표현 계약](../../reference-to-ui/references/ui-composition.md#cta와-선택-컨트롤)을 대조한다. | RUI-12/22, ORC-F10/G18 |
| 정보 추가 후 치수 | 태그/준비물의 마지막 줄이 사진 영역을 벗어나거나 crop이 망가진다. 두 폭·긴 문구·확대에서 사진/정보의 상하단과 높이 소유권을 확인한다. 원래 의도한 비대칭은 보존한다. | RUI-09/22, [요소 계약](../../reference-decompose/references/element-contract.md#반복-묶음과-컨트롤의-표현-계약) |
| 제한적 작은 글자 | 공간 부족을 이유로 본문·시간·행동·입력·필수 안내까지12px로 줄인다. 기본14px와 선언된 짧은 정적 보조정보 예외를 구별하고 상세/확인의 중요 조건을 보존한다. | RUI-09, [글자 하한](../../reference-to-ui/references/ui-composition.md#글자-크기-하한) |
| 선택 컨트롤 | 일부 마감 문구가 자신과 형제 높이를 늘린다. 상태별 외곽·레이블·부모 stretch를 대조하고 불가 선택은 실제로 막고 비활성 의미를 전달한다(네이티브 disabled 또는 위젯에 맞는 ARIA와 이벤트 처리). 셀렉트는 닫힌 외형/옵션 팝업/키보드 동작의 구현 범위를 구별한다. | RUI-21/23, [치수 안정성](../../reference-to-ui/references/design-tokens.md#반복-컨트롤의-상태별-치수-안정성) |
| 시간과 스크롤 | 짧은 선택지가 과하게 넓거나 가로 넘김 단서가 없다. 긴 시간열은 부분 노출·끝항목 터치/키보드 접근·선택 복귀를 확인한다. 숨김 요구는 해당 스크롤바에 적용하고 페이지 가로 넘침으로 대신하지 않는다. | RUI-13/21, [모바일](../../reference-to-ui/references/mobile.md) |
| 불필요한 스크롤 | 빈 상태/짧은 목록인데 움직인다. 실제 viewport·문서/컨테이너 높이·휠 이동량·중첩 패딩을 확인한다. 정상 긴 내용과 확대는 스크롤을 보존하며, 탄성 이동과 접근 불가 가림을 구별한다. | RUI-13/22, [구성 기준](../../reference-to-ui/references/ui-composition.md) |

| 저장/선택의 시각 상태 | 값·ARIA만 바뀌고 하트가 여전히 빈 모양이다. 클릭/터치 직후, hover 중/해제 후, 키보드, 재진입·새로고침에서 실제 채움/윤곽/색과 데이터가 일치하는지 확인한다. | RUI-04/12, 요소 계약 |
| 호버와 포커스 | 필요 없는 테마 hover가 공통 버튼 규칙에서 전파되거나 클릭 테두리를 없애며 키보드 초점도 지운다. 채택한 hover만 유지하고 pointer/Tab 전환, 입력 caret, 프로그램 초점 복귀, 고대비 경계/선택을 확인한다. blur로 해결하지 않는다. | RUI-23, 토큰의 상태 전환·경계 기준 |
| 내역 조회 편의 | 조회 기간/건수/정렬을 알 수 없거나 기간 라벨만 바뀐다. 기준 날짜·기간 경계·시간대·취소 포함 여부를 정하고 실제 범위·결과 수를 일치시킨다. 다른 달/경계/빈 결과/재로드/취소로 확인한다. | RUI-04/05/24, 제품 판단 |

## 잘못된 수정을 고착하지 않기

- 내부 PASS 뒤 새 사용자 실패가 들어오면 판정 범위를 교정한다. ‘스타일은 주관적’이라는 이유로 해제하지 않는다. 미완료를 다른 영역의 성공으로 덮지 않는다.
- 레퍼런스 분석 → 요소별 입력/구현 → 조립 → 제품 각색의 성공은 서로 다르다. 재현 성공을 재조합 품질의 증거로 대체하지 않는다.
- 한 문제를 해결하며 다른 문제를 만들었는지 확인한다. 예: 첫 화면 노출을 위해 외부 여백 압축, 조건 강조를 위해 같은 조건 분리, 위계를 위해 중복 그룹 제목 추가, 상태 스타일로 항목 경계 덮기.
- 보편 규칙에는 적용 조건과 반례를 둔다. 카페 사례의20px,gray50,붉은 취소 버튼,1/3/12개월은 해당 제품의 결정이다. 다른 제품에서도 목적·대상·위계·색의 역할·기간 경계를 판단해야 한다.

## 완료 전에 기록할 결과

`피드백 ID | 현재 규칙/적용처 | 관찰·행동 근거 | fixed-and-verified / not-verified / accepted-difference | 다음 검증`으로 기존 리뷰에 연결한다. 사용자 원문 전체를 복제하지 않아도 요구·교정 이유를 빠뜨리지 않는다. 검증 시나리오에는 기본뿐 아니라 변경 때문에 영향을 받는 빈/긴/상태/다른 탭을 포함한다.

과거 소스·입력·이미지·FAIL은 보존하고 현재 화면/문구/데이터 계약은 최신 상태로 읽히게 한다. 기존 증거 재사용은 **변경없는 속성과 상태**를 명시한다. 바뀐 DOM/문구/행동을 가리키는 옛 PASS 문장을 현재 보고서에 남기거나, 소스 해시만 새로 계산하여 새 시각·행동 검증처럼 포장하지 않는다. 스크립트의 증거 무결성 PASS와 실제 사용성 판독, 스킬 형식 검사와 독립 행동 실험을 구별한다.

## 화면 일부의 개선을 전체 완성으로 확대하지 않기

아이콘 간격, 항목 표면, 주요 행동 위치, 진입점, 페이지 마무리는 서로 다른 실패 범위다. 교정할 때 `사용자 문제 → 관계/원인 → 조건부 기준 → 적용처 → 시각·행동 증거`로 연결한다. 표면을 제거하거나 라벨을 줄이는 것은 수단이며 항목 소속·행동 식별·접근성의 개선 여부로 판단한다. 요소의 단순화로 전체 사용성이 좋아졌다고 자동 판정하지 않는다.

랜딩의 첫 화면과 작성 CTA가 동작해도 끝부분의 탐색·서비스 정보와 도구 재진입은 별도 확인한다. [구성 계약](../../reference-to-ui/references/application-format.md#랜딩과-연결된-도구의-구성-계약)을 사용한다. 같은 사용자에게 여러 제품의 교정을 받았으면 공통으로 적용할 판단과 제품 한정 선택을 분리해 누락 없이 대응표로 남긴다. 특정 간격·색·아이콘 방향·고정 CTA·푸터 열 수를 공통 정답으로 복제하지 않는다.
