# 플로우 계약

## 필수 구조

- 목적/시작점/완료 조건, 사용자와 플랫폼, 확정 요구와 가정.
- 관찰 지도: R/O-ID → 실제 확인한 화면/전이 범위 → observed / user-reported. 추정 순서는 observed로 쓰지 않는다.
- 상태 표: S-ID, 화면/상태, required/proposed 근거, 수집 데이터, 주요 행동.
- 전이 표: T-ID, from, trigger/guard, processing, success, failure/unknown, 데이터 보존, back/re-entry.
- Do/Avoid/Intentional differences/Unknown.
- 검증 경로: 대상 S/T-ID, 조건·행동·기대 결과, 실제 실행 상태.

화면과 상태는 일대일일 필요가 없다. 한 화면 안의 loading/error/success도 상태로 모델링할 수 있다. 입력 데이터를 유지한다고 할 때 메모리/새로고침/세션 종료 중 어느 범위인지 명시한다. 비밀번호나 민감한 입력을 편의상 localStorage에 저장하는 정책을 자동 추가하지 않는다.

## 가상 예시: 이메일 가입

레퍼런스 R2는 개인정보 동의 화면 한 장만 사용자에게 전달받았다. 우리 요구는 이메일 가입, 선택적 마케팅 동의, 기존 계정 처리, 네트워크 복구다. 아래 순서와 전이는 모두 proposed이며, 실제 서비스의 인증/API 정책을 확인한 것이 아니다.

완료 조건: 서비스가 계정 생성과 필요한 인증 완료를 확인한 뒤 제품 진입. 인증 방식은 unknown이다. 기존 계정은 기존 로그인/복구 경로로 연결한다.

| 상태 | 역할 | 근거/종류 | 주요 행동 |
|---|---|---|---|
| S1 | 이메일·필수 인증 입력 | 사용자 이메일 가입 요구 / proposed | 계속 |
| S2 | 동의 선택 | R2의 화면 구성을 참고, 실제 필수 항목 정책 unknown / proposed | 가입 요청, 뒤로 |
| S3 | 처리 중 | 중복 제출 방지 필요 / proposed | 반복 제출 방지, 상태 안내 |
| S4 | 결과 미상/확정 오류 | 네트워크 복구 요구 / proposed | 가능한 상태 확인/복구, 범위 미확정이면 안내 |
| S5 | 기존 계정 경로 | 사용자 요구 / proposed | 기존 로그인/복구 진입 |
| S6 | 가입 완료 | 완료 조건 / proposed | 제품 진입 |

| 전이 | from·trigger/guard | 처리/성공 | 실패·미상 | 데이터·뒤로·재진입 |
|---|---|---|---|---|
| T1 | S1 계속, 유효 입력 | 인증/계정 분기 계약에 따라 S2 또는 S5 | 입력 오류는 S1, API 오류는 그 상태 유지 | 현재 세션의 비민감 입력 유지. 계정 존재 여부 노출은 기존 인증 정책 따름 |
| T2 | S2 가입 요청, 필수 조건 충족 | S3 → 확인된 완료면 S6 | 확정 오류/결과 미상은 S4 | 선택 동의 거절로 막지 않음. S3에서 중복 제출 방지. 제출 전 뒤로는 S1, 세션 내 선택 유지 |
| T3 | S4 복구, 서버 계약에서 허용 | 완료 확인 S6, 미처리 확인 후에만 안전한 재시도 | 확인 API 없으면 unknown 유지, 자동 재제출 없음 | S3/S4에서 뒤로 가도 진행 중 요청이 취소됐다고 가정하지 않음. 재진입 시 기존 인증/상태 확인 가능 범위 적용 |
| T4 | S5 로그인/복구, 기존 서비스 경로 사용 | 인증 성공 시 제품 진입 | 해당 서비스 오류 상태 | 신규 가입을 재실행하지 않음. 뒤로는 S1 |
| T5 | S6 재진입 | 유효 세션이면 제품 진입 | 세션 만료면 기존 인증 진입 | 동의/가입을 임의 재요청하지 않음 |

S1의 인증 방식, T1 기존 계정 판별, T2 계정 생성, T3 조회/멱등성은 **제품/API 의존성**이다. 지원되는 endpoint가 있다는 주장이 아니다. 새로고침 후 복원할 정보와 저장 위치는 실제 인증·개인정보 정책을 확인해 정한다. 미확정 상태에서는 메모리 유지와 영구 저장을 같은 정책으로 쓰지 않는다.

Do: 최소 필수 입력과 명확한 선택 동의, 상태별 복구. Avoid: 세 단계로 보이게 만들기 위한 환영 화면, 선택 동의 강제, 레퍼런스에 없는 성공 전이를 관찰로 포장. Intentional differences: 우리 이메일 가입 요구에 따라 R2 앞뒤 단계를 새로 설계. Unknown: 실제 필수 동의, 인증/계정 정책, 상태 확인·취소·복구 지원.

## 검증 경로

| 경로 | 기대 결과 | 현재 상태 |
|---|---|---|
| S1 → S2 → S3 → S6, 선택 동의 거절 | 필수 조건 충족 시 완료 가능 | 명세 예시, not-verified |
| S2 뒤로 S1 다시 S2 | 정의한 세션 내 입력/선택 보존 | not-verified |
| S3 중 반복 클릭 | 요청 중복 실행 방지 | not-verified |
| S3 응답 유실 → S4 | 결제/가입 결과를 추정하지 않고 지원된 확인 절차만 사용 | not-verified |
| 기존 계정 S5 | 신규 계정 생성 대신 기존 경로 사용 | not-verified |
| 새로고침·중단 후 재진입 | 인증·서버 계약에 따른 상태 복원, 무단 재제출 없음 | 정책 의존, not-verified |

그럴듯한 정상 경로 다이어그램만으로 검증을 완료하지 않는다. 실제 실행이 가능할 때 각 경로에 근거와 결과를 갱신한다.
