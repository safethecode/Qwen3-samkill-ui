# 분석과 문서 계약

## 분석 결과를 문서로 옮기기

필요한 분석 항목만 적용하되 확인되지 않은 값을 채우지 않는다.

| 분석 대상 | 남길 결정과 근거 |
|---|---|
| 제품/사용자 | 핵심 과제, 성공 상태, 정보·행동 순서, 기존 브랜드의 범위 |
| 레퍼런스 | 직접 확인한 화면/영역, 채택할 장점과 이유, 제외와 의도적 차이, 출처 링크 |
| 관계/배치 | 요소 필요성·적용 범위·그룹 관계·시선 흐름, 공통 컨테이너 여백과 예외 |
| 토큰 | 색상 역할, 글자, 간격, 반경, 경계/그림자, 출처·별칭·실제 사용 파일 |
| 컴포넌트 | 배경/글자/아이콘/경계 묶음, 크기·패딩·상태, 아이콘 의미와 출처 |
| 상태/모션 | hover/pressed/focus/error/disabled, 시간·곡선, 레이아웃 안정성, reduced-motion |
| 문구 | 한국어 표현과 불필요한 안내/중복 제거, 행동·조건의 정확성 |
| 검수 | 구체 제외 항목, 예외 범위, 실패 이력 링크, 실제 검증과 남은 미확인 |

각 값에 `existing-token / measured / estimated / chosen`과 근거 위치를 연결한다. image-px를 CSS-px로 단정하지 않는다. 불일치는 `기존 문서 | 구현 | 현재 요구 | 결정/미결 | 영향 범위`로 비교한다. 최신 요구가 명확하면 적용하고, 결과를 좌우할 필수 결정이 불명확하면 해당 부분은 미결로 둔다.

## 새 문서의 형식

참고한 [Google design.md 명세](https://github.com/google-labs-code/design.md/blob/9bf8eae67128b6cc55ad9bf86665767deb4c11cd/docs/spec.md)는 alpha이며 Markdown 본문과 선택적 YAML frontmatter를 다룬다. 확인 revision: `9bf8eae67128b6cc55ad9bf86665767deb4c11cd`. 이후 공식 도구 호환성이 필요하면 해당 버전 명세를 다시 확인한다.

새 문서의 해당하는 `##` 섹션은 아래 순서를 따른다. 본문은 한국어로 작성해도 된다. 관련 없는 섹션은 이유를 밝히고 생략할 수 있다.

1. Overview: 제품 목적, 사용자, 디자인 방향, 적용 범위와 근거/상태.
2. Colors: 실제 색상 역할과 조합, 토큰 원본 연결.
3. Typography: 글자 역할·크기·줄높이·굵기·줄바꿈. 이 패키지는 기본14 CSS px를 유지하고 [글자 기준](../../reference-to-ui/references/ui-composition.md#글자-크기-하한)을 충족한 보조정보에만 최소12px 예외를 허용한다. 외부 예시의12px를 자동 복사하지 않고 적용 범위·근거·검증을 문서에 남긴다.
4. Layout: 정보 위계·요소 관계·반응형·패딩 소유권·스크롤.
5. Elevation & Depth: 표면 단계와 경계/초점 표현, 필요 없는 장식 제외.
6. Shapes: 반경·아이콘 계열과 의미/정렬.
7. Components: 실제 필요한 조합·상태·모션·문구와 사용처.
8. Do's and Don'ts: 구체 채택/제외, 적용 조건·이유, 실패/검수 문서 링크.

YAML을 쓰면 `name`, 선택적 `version/description/omitted`, `colors/typography/rounded/spacing/components` 등의 명세에 맞춰 확정값만 넣는다. 토큰 참조는 `{colors.primary}`처럼 실제 존재하는 경로를 가리킨다. 문서 외부 CSS 변수를 이 문법으로 연결했다고 주장하지 않는다. 모션 등 확장 기준은 본문이나 기존 토큰 파일로 연결하고 공식 schema에 없는 필드를 표준인 것처럼 말하지 않는다. 필요 없는 필드를 채우려고 임의 디자인을 만들지 않는다.

기존 YAML·문장·확장 섹션은 먼저 읽고 보존한다. 공식 형식을 따르지 않는 기존 문서도 유효한 프로젝트 맥락이다. 형식 정리가 필요하면 기존 의미와 현재 결정을 보존하는 변경만 한다. 형식 lint, 코드 토큰 일치, 실제 미관/행동 검증은 별개다.

## 문서 간 책임

- 루트 DESIGN.md: 현재 유효한 제품 디자인 기준과 관리 원본/상세 근거의 진입점.
- 기존 design-contract.md: 화면별 D/E/Q 대응과 검증 조건. 경로 이동을 강제하지 않는다.
- 레퍼런스 문서: 출처와 원본 관찰. 구현 결과로 원본 관찰을 덮어쓰지 않는다.
- 리뷰/ledger: 실패·수정·재검증 이력. 현재 문서로 이력을 대체하지 않는다.

분석 대상 레포에 적용한다. 스킬 설치 위치에 대상 제품 문서를 만들지 않는다. 문서만 작성한 작업을 UI 구현 완료로 보고하지 않는다.
