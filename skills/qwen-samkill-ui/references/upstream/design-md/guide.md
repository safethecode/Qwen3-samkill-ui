# 분석해서 DESIGN.md 만들기

작업 대상 레포 루트의 `DESIGN.md`에 현재 디자인 기준과 이유를 보존한다. 실제 자료를 분석해 작성하며 예쁜 형용사나 예시 팔레트를 채워 넣지 않는다. 기존 파일이 있으면 먼저 읽고 적용한다.

## 범위와 기존 자료

1. 사용자가 지정한 대상과 Git 루트를 확인한다. 현재 셸 위치, 스킬 저장소, 대상 앱 경로를 혼동하지 않는다. Git이 없으면 명시한 프로젝트 루트를 쓴다. 모노레포는 루트 문서가 앱별 범위와 하위 문서를 연결하며 서로 다른 브랜드를 하나로 강제하지 않는다.
2. 대상 `AGENTS.md`, 루트 `DESIGN.md`, 기존 디자인 계약·토큰·테마·공통 컴포넌트와 관련 화면을 읽는다. 파일 경로·제품 범위·자료의 확인 상태를 기록한다. 대소문자만 다른 기존 파일도 먼저 확인한다.
3. 현재 사용자 요구가 기존 결정과 다르면 변경 범위와 이유를 기록한다. 알 수 없는 브랜드·실측값을 만들어내지 않는다. 기존 문서의 사용자 섹션·확장 필드·이력은 보존하고 필요한 부분만 갱신한다. 읽기 전용 리뷰 요청에서는 파일을 만들거나 수정하지 않고 누락과 수정안을 보고한다.

## 분석

[분석과 문서 계약](references/document-contract.md)을 읽는다. 필요한 자료가 이미 있으면 재검색하지 않는다. 자료가 없고 UIbowl 조사가 필요하면 `uibowl-research`, 제품 배치와 토큰 판단에는 `reference-to-ui`의 관련 기준을 사용한다. 해당 스킬이 없으면 동일한 분석 항목을 직접 수행한다.

- 사용자의 핵심 과제와 정보/행동 순서, 요소 간 관계와 위계, 왜 유지·변경·제외하는지 판단한다. Todo 등 특정 사례의 좌표나 행 구성을 복제하지 않는다.
- 기존 코드의 토큰 정의 → 별칭 → 실제 사용을 추적한다. 화면별 공통 패딩, 글자 역할, 표면, 아이콘, 상태·모션의 일치와 차이를 확인한다. 레거시 구현의 모든 값을 정답으로 승격하지 않는다.
- 실제 본 레퍼런스의 장점을 R/O/Q-ID와 연결하고 관찰·추정·제품 결정·미확인을 구분한다. 정지 화면으로 포커스·모션·스크롤 동작을 추정하지 않는다.
- 입력 근거가 부족하면 확인된 범위의 초안을 작성하고 부족한 결정과 다음 확인을 명시한다. 확정 토큰 필드에 가짜 값이나 `unknown` 색상값을 넣지 않는다.

## 작성과 갱신

루트 `DESIGN.md`를 현재 기준의 진입점으로 만든다. 새 문서는 Google design.md의 Markdown 구조와 필요할 때 YAML 토큰을 따른다. 기존 문서 형식이 다르면 강제 변환하지 않는다. 표준 형식과 이 패키지의 추가 검수 규칙을 구별한다.

작은 프로젝트는 문서 안에서 기준을 완결하고, 상세 레퍼런스·계약·리뷰·실패 이력이 이미 있으면 요약과 정확한 링크로 연결한다. 기준값의 관리 원본을 하나로 정하고 문서/코드의 관계를 명시한다. 코드가 원본이면 토큰 경로와 필요한 값의 대응을 기록하고, 문서가 원본이면 구현에 반영할 매핑을 명시한다. 서로 다른 두 기준을 조용히 유지하지 않는다.

작성 요청만으로 제품 코드·패키지·브랜드·배포를 변경하지 않는다. CLI 설치를 강제하지 않는다. UI가 없는 레포는 그 범위를 설명하고 미정 팔레트/폰트를 만들어내지 않는다. 명세 문서 완성과 구현/시각 검증 완료를 구별한다.

## 검증과 전달

파일 존재, 적용 범위, Markdown 링크, YAML이 있다면 구문·값·참조, 기존 내용 보존, 문서와 토큰의 충돌을 확인한다. 문서의 값과 역할이 실제 코드/관찰과 맞는지 표본이 아닌 변경 범위 전체에서 확인한다. Google CLI가 이미 있거나 형식 호환 검증을 요청받으면 버전에 맞는 검사를 실행하고 결과를 남긴다. 실행하지 않은 공식 lint나 UI 렌더를 통과했다고 하지 않는다.

검토에 필요한 DESIGN.md와 연결 계약/토큰을 프로젝트 게이트의 대상에 포함해 문서 변경 뒤 낡은 근거를 재사용하지 않게 한다. 종료 시 경로, 분석 자료, 주요 결정·변경 이유, 검증과 남은 미확인을 전달한다. 제품 구현 시 이 문서를 읽어 반영하고, 결정이 바뀌면 코드·문서·리뷰 근거를 함께 갱신한다.
